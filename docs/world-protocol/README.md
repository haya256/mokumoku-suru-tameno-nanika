# もくもくワールド接続プロトコル (mokumoco-world)

もくもく会チャットの「ワールドマップ」で、**別のサーバー(別のもくもくルームや、それ以外の空間)とつながる**ための公開仕様です。
このフォルダだけを別プロジェクトに渡せば、「この仕様に準拠したWebアプリ」を作れるように書いています。

- 現行版: **v1.0**(→ [`v1/spec.md`](v1/spec.md))
- 文書の言葉づかい: 「〜しなければならない」= 必須、「〜すべき」= 強い推奨(理由があれば外してよい)、「〜してよい」= 任意

## 全体像

```
 参加者のブラウザ ──(2秒ごと)──▶ 接続側サーバー ──(5秒以上の間隔で巡回)──▶ 提供側サーバー
                                 (つなぐ側)                                  (つながれる側)
                                     │  ① GET /.well-known/mokumoco-world   … 対応版の確認(登録時)
                                     │  ② GET <snapshot URL>               … 空間とチャットの全状態
                                     │  ③ GET 画像URL(部屋・キャラ・チャット画像) … 変わったときだけ
                                     ▼
                         取ってきた内容を自分の参加者に中継して表示
```

- **提供側**: 自分の空間(部屋・在室者・チャットなど)を読み取り専用のJSONと画像で公開するサーバー
- **接続側**: 提供側を巡回して、取ってきた内容を自分の画面(ワールドマップのマス・チャット欄)に混ぜて表示するサーバー
- 1つのサーバーが両方を兼ねてよい(もくもく会チャット本体は両方を兼ねる)
- 参加者のブラウザは原則として提供側に直接アクセスしません。接続側サーバーが取ってきて中継します。
  例外は**動画・音声ストリームだけ**で、これはブラウザが提供側(または配信元)のURLを直接再生します([`v1/spec.md` §6](v1/spec.md#6-メディアの扱い))

## 公開性について

この仕様で公開する情報(在室者の名前・作業内容・チャット・画像)は、**誰でも閲覧できる前提**のものです。
もくもく会チャットでは閲覧は誰でも自由で、合言葉は「書き込み」を制限するためだけのものです。
提供側はこの前提で公開してよい情報だけをスナップショットに載せてください。

## 準拠した実装を作るには(チェックリスト)

### 提供側を作る場合
- [ ] `GET /.well-known/mokumoco-world` で Discovery 文書を返す(§2)
- [ ] Discovery に書いた URL でスナップショットを返す(§3)
- [ ] スナップショットの `space` に対応する空間種別(`room9` など)の中身を入れる(§4)
- [ ] チャットを `ts`(UNIX秒)付きで返す(§5)
- [ ] スナップショットに書いた画像URLで画像を返し、中身が変わったら `version` を変える(§6)
- [ ] 認証なしの GET で取れるようにする
- [ ] `v1/schemas/snapshot.schema.json` で自分の応答を検証する

### 接続側を作る場合
- [ ] Discovery で対応する最大の版を選ぶ。無ければ接続しない(または `legacy.md` の方式を試す)
- [ ] 提供側の `minPollIntervalSec` 以上の間隔で巡回する(§7)
- [ ] **知らないフィールド・知らない空間種別・知らない値を無視する**(`versioning.md`)
- [ ] 取ってきたテキストはエスケープして表示し、画像は中身(マジックバイト)を確かめてから中継する(§8)
- [ ] 取得に失敗しても前回の内容を残し、「接続できません」と表示する(§7)
